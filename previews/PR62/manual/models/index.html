Adding functions to a model

Convenience methods

For univariate and bivariate functions, piecewiselinear takes the breakpoints and the function, or its values at the breakpoints, and returns the output:

using JuMP, PiecewiseLinearOpt, HiGHSmodel = Model(HiGHS.Optimizer)set_silent(model)@variable(model, 0 ≤ x ≤ 4)@variable(model, 0 ≤ y ≤ 4)cost_x = piecewiselinear(model, x, [0, 1, 2, 4], [0, 3, 4, 5])cost_y = piecewiselinear(model, y, 0:4, t -> sqrt(t); method = ZigZagBinary())@constraint(model, x + y == 5)@objective(model, Min, cost_x + cost_y)optimize!(model)value(x), value(y), objective_value(model)
(0.9999999999999991, 4.000000000000001, 4.999999999999997)

The inputs may be variables or affine expressions, and keyword arguments choose the method, the direction and the triangulation of bivariate functions.

The general method

The general method takes a PWLFunction and a vector of inputs, and returns a vector of outputs together with a PWLFormulation:

using JuMP, PiecewiseLinearOpt, HiGHSmodel = Model(HiGHS.Optimizer)set_silent(model)@variable(model, x[1:2])pwl = BivariatePWLFunction(0:0.5:2, 0:0.5:2, (a, b) -> a * b)z, formulation = piecewiselinear(model, x, pwl; name = "product")formulation
PWLFormulation "product" using K1(LogarithmicEmbedding()) with 32 variables and 16 constraints

The formulation holds the variables and constraints that were added. Their names start with the name given, or pwl1, pwl2, … by default:

formulation.variables[1:3]
3-element Vector{JuMP.VariableRef}:
 product_y[1]
 product_λ[1,1]
 product_λ[2,1]

Deleting the formulation removes the function from the model again:

delete(model, formulation)num_variables(model)
2

Outputs and directions

By default, new output variables are created, bounded by the smallest and largest function values. Existing variables or expressions can be given with output_vars in the general method, or output_var in the convenience methods.

The direction keyword relaxes the equality between output and function value, see Direction, and the new output variables are then only bounded from the side of the function. For example, with Epigraph the output is only bounded from below, which is enough when minimizing:

using JuMP, PiecewiseLinearOpt, HiGHSmodel = Model(HiGHS.Optimizer)set_silent(model)@variable(model, x)y = piecewiselinear(    model,    x,    [0, 1, 2, 3],    [2, 0, 1, 0];    direction = Epigraph(),)@objective(model, Min, y + x / 10)optimize!(model)value(x), value(y)
(1.0, 0.0)

The relaxed direction gives the same optimum whenever a smaller output is never worse with Epigraph, or a larger output with Hypograph. This is the case when the output only appears in the objective with the right sign, e.g. a cost that is minimized or a revenue that is maximized, or in a constraint that a larger output (smaller for Hypograph) only makes harder to satisfy, e.g. a cost in cost ≤ budget. The relaxed direction is then recommended, as it is typically about 10% faster to solve, and up to 30% for some methods.

Several outputs

A function with several outputs shares the formulation between them, which is cheaper than formulating each output separately:

using JuMP, PiecewiseLinearOpt, HiGHSxs = [0.0, 1.0, 2.0]segments = [    SegmentPointRep{1,2}(        [(xs[i],), (xs[i+1],)],        [(sin(xs[i]), cos(xs[i])), (sin(xs[i+1]), cos(xs[i+1]))],    ) for i in 1:2]pwl = PWLFunction(segments, Intervals())model = Model(HiGHS.Optimizer)set_silent(model)@variable(model, x)(s, c), _ = piecewiselinear(model, [x], pwl)@objective(model, Max, s + c)optimize!(model)value(x), value(s), value(c)
(1.0, 0.8414709848078965, 0.5403023058681398)

Separable reformulation of products

A bivariate function that is built from products and univariate terms can instead be written as a sum of univariate functions of linear expressions (D'Ambrosio, Lodi and Martello, 2010), using

\[x y = \frac{1}{4} \left((x + y)^2 - (x - y)^2\right).\]

As the inputs of piecewiselinear may be affine expressions, each square is a univariate function of x + y or x - y. The univariate functions are cheaper than a bivariate function on a grid, so they can use many more breakpoints, which matters most when the optimum is not near the grid points. Each term can also use the direction that suits its sign. For example, to maximize x y subject to x + 2y ≤ 4:

using JuMP, PiecewiseLinearOpt, HiGHSmodel = Model(HiGHS.Optimizer)set_silent(model)@variable(model, 0 ≤ x ≤ 4)@variable(model, 0 ≤ y ≤ 2)@constraint(model, x + 2y ≤ 4)square(t) = t^2 / 4# x + y is in [0, 6] and x - y in [-2, 4]u = piecewiselinear(model, x + y, 0:0.25:6, square; direction = Hypograph())# The square is convex, so its epigraph needs no binary variablesv = piecewiselinear(model, x - y, -2:0.25:4, square; method = ConvexPieces(), direction = Epigraph())@objective(model, Max, u - v)optimize!(model)value(x), value(y), objective_value(model)
(2.000000000000001, 0.9999999999999996, 2.0000000000000027)

Whether this is faster than a bivariate grid formulation depends on the problem and the solver, so it is worth comparing the two on representative instances.

BivariatePWLFunction(x, y, f::Function; triangulation = K1Triangulation()) BivariatePWLFunction(x, y, z::AbstractMatrix; triangulation = K1Triangulation())

The piecewise linear function on the grid with breakpoints x and y, which interpolates f(x[i], y[j]), or z[i, j], at the grid points.

ConvexPieces(encoding = :mc)

Formulation of univariate piecewise linear functions with a binary variable for each convex piece.

Epigraph()

The direction where the outputs are at least the function value, y >= f(x), which suffices when the function is minimized.

Hypograph()

The direction where the outputs are at most the function value, y <= f(x), which suffices when the function is maximized.

Intervals()

The segments of a univariate function or relaxation, which lie over intervals.

PWLFunction(segments::Vector{SegmentPointRep{D,F}}, structure::SegmentStructure{D})

A piecewise linear function from R^D to R^F, given by its segments.

SegmentPointRep{D,F}(input_vals, output_vals)

A piece of a piecewise linear function from R^D to R^F, given by the points input_vals and the function values output_vals at them.

ZigZagBinary()

The binary zig-zag formulation of univariate continuous piecewise linear functions (Huchette and Vielma, 2023).

piecewiselinear( model, input_vars, pwl::PWLFunction; method, direction = Graph(), output_vars = nothing, name = nothing, )

Adds the piecewise linear function pwl of input_vars to model, and returns the tuple (output_vars, formulation).

segments(pwl::PWLFunction{D,F})

The segments of pwl, a vector of SegmentPointRep{D,F}.
