Formulation methods

The method keyword of PiecewiseLinear chooses how a function is formulated with auxiliary variables and constraints. All methods give a correct model; they differ in size and in how fast a solver finds the optimum. Which method is fastest depends on the problem and the solver, so it is worth trying a few methods on representative instances. See Huchette and Vielma (2023) for a computational comparison.

Choosing a method

The following advice is based on computational tests with HiGHS and Xpress on transportation problems with concave and discontinuous costs, resource allocation with S-shaped utilities, and bivariate functions on grids.

  • Univariate functions: the default Logarithmic is a sound choice. The other logarithmic methods (LogarithmicIndependentBranching, IndependentBranching, ZigZagBinary, ZigZagInteger and DisaggregatedLogarithmic) perform similarly, each within about 30% of the others.
  • With a solver that supports SOS2 constraints, e.g. Gurobi or Xpress, try NativeSOS2 first. It was the fastest method with Xpress, often by a large margin.
  • For minimizing concave costs and for discontinuous functions, MultipleChoice was the fastest method with HiGHS, and second only to NativeSOS2 with Xpress, despite its d binary variables. It explores far fewer nodes than the logarithmic methods on such problems.
  • For functions with convex stretches in the Epigraph direction (concave in the Hypograph direction), e.g. S-shaped utilities that are maximized, ConvexPieces only needs binary variables for the convex pieces rather than for the segments. It was 2 to 3 times faster than MultipleChoice on S-shaped functions, and a function that is convex in the direction needs no binary variables at all.
  • Bivariate functions: use a grid method. With HiGHS, GreedyTriangleSelection and OptimalTriangleSelection were the fastest on any triangulation, and K1 and UnionJack on their own triangulations. With a solver that supports SOS2 constraints, the grid methods are close to each other, and NativeSOS2 as the axis method, e.g. SixStencil(NativeSOS2()), was about three times faster than the default axis method.
  • Avoid ConvexCombination and Incremental, which were never competitive, and ConvexCombination, MultipleChoice and DisaggregatedLogarithmic for bivariate functions, except on very small grids.
  • Use the Epigraph or Hypograph direction when it is valid, see Outputs and directions. This is typically 10% faster, and up to 30% for MultipleChoice, Logarithmic and DisaggregatedLogarithmic.

Below, d is the number of segments of a univariate function.

A relaxation, see UnivariatePWLRelaxation, is a band between a lower and an upper piecewise linear bound. The two methods that support it model both bounds with one set of binary variables.

NativeSOS2 leaves the branching to solvers that support SOS2 constraints, e.g. Gurobi or Xpress; for other solvers, such as HiGHS, MathOptInterface reformulates the constraint with binary variables, which is much slower than the other methods.

The number of binary variables is only one measure of the size of a formulation. The logarithmic methods have few binary variables but denser constraints: their number of nonzero coefficients grows like d * log2(d), against d for the linear-size methods, although for a few hundred segments the difference is within a factor of two. The figure counts both for a function with d segments:

Bivariate functions

Bivariate functions are defined on a grid, where each cell is split into two triangles. The default method depends on the triangulation: K1 for K1Triangulation, UnionJack for UnionJackTriangulation and GreedyTriangleSelection for the others.

The grid methods select a cell with an SOS2 constraint along each axis, formulated with any univariate method in the table above (the axis_method, by default Logarithmic), and then select a triangle in the cell:

MethodTriangle selectionTriangulation
SixStencilup to 6 binaryany
NineStencilup to 9 binaryany
GreedyTriangleSelectionfew, typically 2 to 5, found by a heuristicany
OptimalTriangleSelectionsmallest number, typically 2 to 4, computed with a solverany
K12 binaryK1Triangulation
UnionJack1 binaryUnionJackTriangulation

With n₁ × n₂ grid points and a logarithmic axis method, the cell selection uses ceil(log2(n₁ - 1)) + ceil(log2(n₂ - 1)) binary variables. For solvers with support for SOS2 constraints, NativeSOS2 is also a good axis method.

GreedyTriangleSelection finds its triangle selection in milliseconds, and typically with the optimal number of binary variables. Proving that number optimal with OptimalTriangleSelection takes about a second for regular triangulations of grids up to 8×8, but can take much longer for irregular triangulations, e.g. BestFitTriangulation or RandomTriangulation. If it takes longer than its time limit, the greedy selection is used. When both the sub-solver and the solver of the model are HiGHS, and the model is solved with a single thread, give the sub-solver a single thread too, i.e. OptimalTriangleSelection(optimizer_with_attributes(HiGHS.Optimizer, "threads" => 1)), as the solve otherwise fails.

OptimalIndependentBranching instead selects a triangle directly with the smallest possible number of binary variables, which is only practical to compute for small grids, up to about 4×4 points.

Functions of more variables

ConvexCombination, DisaggregatedLogarithmic and MultipleChoice formulate functions of any number of variables. The segments must be simplices for MultipleChoice. DisaggregatedLogarithmic, the default, uses the fewest integer variables, ceil(log2(d)) for d segments. Both support discontinuous functions.

Example

Different methods give the same optimum, but different model sizes:

using JuMP, PiecewiseLinearOpt, HiGHSf(a, b) = sin(3a) * cos(2b)pwl = BivariatePWLFunction(0:0.1:1, 0:0.1:1, f)for method in (    SixStencil(),    NineStencil(),    K1(),    GreedyTriangleSelection(),    OptimalTriangleSelection(HiGHS.Optimizer),    SixStencil(IndependentBranching()),    ConvexCombination(),)    model = Model(HiGHS.Optimizer)    set_silent(model)    @variable(model, x[1:2])    (z,), formulation = add_formulation(model, PiecewiseLinear(pwl; method = method), x...)    @objective(model, Min, z)    optimize!(model)    binaries = count(is_binary, formulation.variables)    println(rpad(method, 50), "binaries: ", lpad(binaries, 3), "  minimum: ", round(objective_value(model); digits = 4))end

The logarithmic disaggregated convex combination formulation.

Formulation of bivariate continuous piecewise linear functions on any grid triangulation, which selects the triangle with a few binary variables found by a greedy heuristic.

Incremental()

The incremental formulation of univariate continuous piecewise linear functions (see Vielma, Ahmed and Nemhauser, 2010).

IndependentBranching(scheme::Symbol = :biclique)

Logarithmically sized ideal formulation of univariate piecewise linear functions, based on independent branching over the ordered segments (Lyu, Hicks and Huchette, 2023).

K1(axis_method = Logarithmic())

Formulation of bivariate continuous piecewise linear functions on a K1Triangulation, the default method for it.

MultipleChoice()

The multiple choice formulation of piecewise linear functions of any dimension (see Vielma, Ahmed and Nemhauser, 2010), with a copy of the input and a binary variable for each segment.

NineStencil(axis_method = Logarithmic())

Formulation of bivariate continuous piecewise linear functions on any grid triangulation (Huchette and Vielma, 2023).

OptimalTriangleSelection( sub_solver, axis_method = Logarithmic(); time_limit = 60.0, )

Formulation of bivariate continuous piecewise linear functions on any grid triangulation (Huchette and Vielma, 2023).
