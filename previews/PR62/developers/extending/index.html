Extending the package

A formulation method is a subtype of PWLMethod that implements how a function is added to a model. Three levels of extension are possible, from the least to the most work:

  1. A SOS2Method implements formulate_sos2!, a formulation of the SOS2 constraint on a vector of convex multipliers. The package then formulates continuous univariate functions with it, and it can be used as the axis method of the bivariate grid methods.
  2. A TriangleSelectionMethod implements formulate_triangle_selection!, which selects a triangle in a cell of a grid, after the package has selected the cell with SOS2 constraints along the axes.
  3. Any other PWLMethod implements formulate_pwl!, the whole formulation for the dimensions it supports.

In all cases, every variable and constraint added to the model must be passed through record!, so that the PWLFormulation can report and delete them, and variables should be named with variable_name. The helpers constrain_output! and add_biclique_cover! cover common parts of a formulation. The interface is exported, but adding a method to an interface function requires importing it or writing it with the module prefix.

The methods below are examples of the interface. They are tested, but they are not meant for production use: LinearBranching has a quadratic number of nonzeros, and CellBinaries one binary variable per cell, which makes them slower than the methods of the package.

An SOS2 method

The SOS2 constraint on multipliers $\lambda_1, \ldots, \lambda_n$ requires that at most two, and those adjacent, are nonzero. In the language of independent branching, the multipliers $\lambda_u$ and $\lambda_v$ with $v \ge u + 2$ must not be nonzero together. One way to enforce this uses a binary variable $z_k$ for each $k = 1, \ldots, n - 2$, which separates $\lambda_1, \ldots, \lambda_k$ from $\lambda_{k+2}, \ldots, \lambda_n$:

using JuMP, PiecewiseLinearOpt, HiGHSimport PiecewiseLinearOpt: SOS2Method, formulate_sos2!, add_biclique_cover!struct LinearBranching <: SOS2Method endfunction formulate_sos2!(formulation, λ::Vector, ::LinearBranching)    n = length(λ)    cover = [(collect(1:k), collect(k+2:n)) for k in 1:n-2]    add_biclique_cover!(formulation, λ, cover)    returnend

A triangle selection method

A TriangleSelectionMethod receives the matrix of multipliers of the grid points, of which only the four corners of one cell can be nonzero, and must restrict them to one of the two triangles of that cell. The simplest way is a binary variable for each cell, which separates the two corners that are not joined by the diagonal of the cell, as given by cell_diagonals:

using JuMP, PiecewiseLinearOpt, HiGHSimport PiecewiseLinearOpt:    TriangleSelectionMethod,    formulate_triangle_selection!,    add_biclique_cover!,    cell_diagonalsstruct CellBinaries{M<:PWLMethod} <: TriangleSelectionMethod    axis_method::MendCellBinaries() = CellBinaries(Logarithmic())function formulate_triangle_selection!(    formulation,    λ::Matrix,    nw_se::Matrix{Bool},    ::CellBinaries,)    cover = Tuple{Vector{Tuple{Int,Int}},Vector{Tuple{Int,Int}}}[]    for i in 1:size(nw_se, 1), j in 1:size(nw_se, 2)        _, (a, b) = cell_diagonals(nw_se, i, j)        push!(cover, ([a], [b]))    end    add_biclique_cover!(formulation, λ, cover)    returnend

A general method

For functions that the two kinds above do not cover, e.g. of three or more variables, implement formulate_pwl! for the dimensions D and F the method supports. It receives the inputs and outputs as tuples of Scalars, i.e. variables, expressions or constants, and relates the outputs to the function values with constrain_output!, which takes the Direction into account. The pieces of the function are read with segments, input_values and output_values. Functions that the method does not support should be rejected with an error; the package then removes anything the method added to the model before the error.

As an example, the epigraph of a convex univariate function is the intersection of the epigraphs of its segments, which needs no binary variables:

using JuMP, PiecewiseLinearOpt, HiGHSimport PiecewiseLinearOpt:    Direction,    Scalar,    formulate_pwl!,    constrain_output!,    record!,    segments,    input_values,    output_valuesstruct ConvexEpigraph <: PWLMethod endfunction formulate_pwl!(    formulation,    (x,)::Tuple{Scalar},    (y,)::Tuple{Scalar},    pwl::UnivariatePWLFunction,    ::ConvexEpigraph,    direction::Direction,)    if !(direction isa Epigraph)        error("ConvexEpigraph only formulates the epigraph of a function.")    end    slope = -Inf    for segment in segments(pwl)        (a,), (b,) = input_values(segment)        (fa,), (fb,) = output_values(segment)        if (fb - fa) / (b - a) < slope            error("ConvexEpigraph requires a convex function.")        end        slope = (fb - fa) / (b - a)        constrain_output!(formulation, y, fa + slope * (x - a), direction)    end    # The input is restricted to the domain of the function    breakpoints = [only(p) for s in segments(pwl) for p in input_values(s)]    model = formulation.model    record!(formulation, @constraint(model, x >= minimum(breakpoints)))    record!(formulation, @constraint(model, x <= maximum(breakpoints)))    returnend

The segments of a UnivariatePWLFunction are ordered, so checking that the slopes increase verifies convexity. The method only formulates the epigraph, which is enough when the function is minimized:

model = Model(HiGHS.Optimizer)set_silent(model)@variable(model, x)pwl = UnivariatePWLFunction(-2:2, t -> t^2)(y,), formulation = piecewiselinear(model, [x], pwl; method = ConvexEpigraph(), direction = Epigraph())@objective(model, Min, y - 1.5x)optimize!(model)value(x), value(y), count(is_binary, all_variables(model))
(1.0, 1.0, 0)

The piecewise linear function on the grid with breakpoints x and y, which interpolates f(x[i], y[j]), or z[i, j], at the grid points.

Direction

The abstract type of the direction keyword of piecewiselinear, which gives how the outputs y relate to the function value f(x): Graph (the default), Epigraph or Hypograph.

Epigraph()

The direction where the outputs are at least the function value, y >= f(x), which suffices when the function is minimized.

PWLMethod

The abstract type of the formulation methods, which are passed to piecewiselinear with the method keyword.

PiecewiseLinearOpt.Scalar

The type of the inputs and outputs of a function in a formulation: variables, expressions or constants.

SixStencil(axis_method = Logarithmic())

Formulation of bivariate continuous piecewise linear functions on any grid triangulation (Huchette and Vielma, 2023).

UnivariatePWLFunction(x, f::Function) UnivariatePWLFunction(x, z::AbstractVector)

The piecewise linear function with the strictly increasing breakpoints x, which interpolates f(x[i]), or z[i], at the breakpoints.

UpperTriangulation()

Every cell is split along the diagonal with the larger average of the function values at its end points, which gives the largest interpolant.

add_biclique_cover!(formulation::PWLFormulation, λ::AbstractArray, cover)

Adds the independent branching formulation given by a biclique cover.

Returns the diagonals of cell (i, j) of a grid triangulation as (edge, non_edge), where edge is the diagonal that splits the cell into its two triangles and non_edge is the other.

constrain_output!(formulation::PWLFormulation, y, value, direction::Direction)

Adds the constraint that the output y equals, is at least or is at most the expression value of the function value, as given by direction.
